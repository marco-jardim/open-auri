# Phase 5 test battery (T5.T)

Plan: `docs/plans/2026-10-15-open-auri-web-plano.md`, T5.T (cases at lines ~2405-2418). Three parts:

- **web integration** (this folder, workerd): `npm run -w web test:int`;
- **jobs** (`workers/jobs/test/phase5.test.ts`, workerd): `npm run -w workers/jobs test` (or `npm test` inside `workers/jobs`);
- **staging e2e** (`web/tests/e2e/staging.spec.ts`, Playwright against the deployed staging Worker), run by the orchestrator only:

  ```powershell
  cd D:\git\open-auri\web
  $env:STAGING_ORIGIN = '<staging origin, from the operator environment>'   # never versioned
  # optional, only if staging runs with SIGNUP_ENABLED=true:
  # $env:STAGING_SIGNUP_ENABLED = 'true'
  npx playwright test --project=staging
  ```

  With `STAGING_ORIGIN` set, `playwright.config.ts` has a single project (`staging`), no `webServer` and no `globalSetup` (no local build, no local D1). Without it the `staging` project does not exist and the local projects ignore `staging.spec.ts` (which also skips itself).

The D1 database, KV and R2 are shared between files: every test uses unique ids, never global counts, and never flips the KV read-only switch (the read-only step sees a view of CONFIG, as in `phase4/protections.test.ts`).

## Read-only mode on staging (manual)

The switch is a shared, audited admin action on KV, so no automated test flips it on staging.

1. Sign in on staging with the admin account (2FA) and open `/admin`.
2. Turn the read-only switch on. Wait up to about 60 s (KV propagation; each isolate also caches the value for 10 s).
3. Check, signed out, in a private window: public pages and `GET /api/v1/feed` answer 200; any write (for example the sign-in page with a wrong password still answers, because sign-in is allowlisted; a `POST /api/v1/packs` from a signed-in tab) answers 503 with `x-error-code: READ_ONLY`, `retry-after` and the security headers; a browser form post shows the bilingual "somente leitura" page.
4. Turn the switch off in `/admin` and confirm that a write works again after the propagation delay.
5. Confirm the two entries (on, off) with the admin as actor in the audit page (`/admin/auditoria`).
6. Record the date in the phase report.
